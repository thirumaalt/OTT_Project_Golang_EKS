How HPA works

Metrics Server
→
CPU usage
→
HPA calculates
→
Scale up/down
# Formula desired = ceil(current × (currentCPU / targetCPU)) = ceil(1 × (80/50)) = ceil(1.6) = 2 pods
Cooldown: Scale up = 15s wait. Scale down = 5 min wait (avoid flapping)

Liveness vs Readiness

LivenessReadiness
QuestionIs pod alive?Is pod ready for traffic?
On failRestart podRemove from Service
RunsContinuouslyContinuously
Use casePod deadlockedDB not connected yet

Timing calculation

failureThreshold: 3 periodSeconds: 20 → 3 × 20 = 60s before restart + initialDelaySeconds: 15 = 75s total from pod start
Postgres down scenario: Liveness passes (pod alive) + Readiness fails (can't serve) → pod stays running but gets NO traffic
